# Gridiron T-Rank

A Bart Torvik style ratings site for FBS college football, built by Cayden. The output is one self-contained HTML page (`gridiron-t-rank.html`) with all data embedded. It opens on Game Finder; other tabs are Ratings, Games, Trends, Matchup, Backtest and Method, plus research views reached by links (`#game/<id>`, `#team/<id>`).

Cayden is learning as he builds this. He prefers hints and explanations over just being handed solutions, unless he says he needs something fast. Never use dashes (em dashes or hyphens as punctuation) in writing for him.

## How to rebuild

```
pip install -r requirements.txt
./rebuild.sh        # about 2 minutes, downloads ~1.2 GB the first time
```

Output: `gridiron-t-rank.html` in the project root. The current season's files are re-downloaded on every run, so rerunning the script picks up new results.

Pipeline, in order (all scripts live in `src/`, run from `src/`):

| Step | Script | Output in `data/` |
|---|---|---|
| Download | `fetch_data.py` (season from `season.py`) | `pbp_YYYY`, `sched_YYYY`, `teaminfo_YYYY` parquet files, plus `up_cfb_schedules_2026.parquet` (full schedule including unplayed games) |
| Prep | `prep.py` (uses `build.load_season`) | `prep.pkl`: per team-game rows for every season |
| Walk-forward | `run_bt.py` (uses `model.walk`, `snap=True`) | `bt.pkl`: pregame features for every 2008+ game, plus each side's pregame team snapshot (`h_*`/`a_*` columns) |
| Leak check | `test_analogs.py` | nothing; fails the run if a fingerprint can see its own game or later ones |
| Early years | `pregame.py` | `pregame.pkl`: adds 2004 to 2007 |
| Fit + export | `export2.py` | `site_data.json`: model weights, backtest stats, per-game rows, priors |
| Games | `export3.py` | adds pregame picks for every past game and this season's upcoming games |
| QB context | `qb.py` | adds `qb` to `site_data.json`: each team's main passer last game, his share of passes, and the season attempts leader (`--all` also builds `qb.pkl` for every game since 2004) |
| Player logs | `players.py` | adds `players` ({pid: [name, latest team]}) and `plog` (every passer, rusher and receiver's game line, this season and last) to `site_data.json` |
| Spreads | `lines.py` | keeps `lines_hist.json` (committed): closing and opening spread plus total for every game since 2013, past seasons fetched once, current season refreshed each run. | Market odds | `kalshi.py` | adds live Kalshi odds to upcoming games, logs a snapshot to `kalshi_history.jsonl` |

A GitHub Actions workflow (`.github/workflows/rebuild.yml`) runs this whole pipeline every 3 hours and on manual trigger, commits the updated page, and deploys it to GitHub Pages. The `CFBD_API_KEY` secret in the repo is actually named `CFBAPI`.

## Data sources

- Play-by-play with EPA: sportsdataverse `espn_cfb_pbp` GitHub releases, 2004 onward (nothing earlier exists).
- Schedules: `espn_cfb_schedules` releases (completed games only) and the cfbfastR-data repo's `schedules/parquet/cfb_schedules_YYYY.parquet` (CFBD based, includes upcoming games).
- Team info, conferences, FBS classification: cfbfastR-data `team_info/parquet/cfb_team_info_YYYY.parquet`.
- Game ids and team ids are ESPN ids across all sources.
- Coverage: 2004 is 66% of FBS games, 2005 to 2007 are 84 to 90%, 2020 is 81%, everything else 96%+.

## The model

Per stat, a weighted ridge regression over team-games: `value = mu + off[team] + def[opponent] + hfa*loc`, where loc is +1 home, -1 away, 0 neutral. The penalty pulls each team toward a prior: last season's final value times 0.9 (new FBS teams start at the 20th percentile).

Three stats feed the rating (chosen by walk-forward testing on 2008 to 2024):

- `PTS`: points scored per game, weight 1 per game, lambda 3
- `SR`: success rate, weighted by plays, lambda 100
- `NT`: EPA per play with turnover plays removed, lambda 100

Rating = NT net * NT beta + SR net * SR beta + PTS net * PTS beta (net = off minus def), refit each pipeline run so the exact numbers drift slightly; printed by `export2.py` as `beta`. That's projected margin vs an average team on a neutral field. Home field is also refit each run (the 4th beta value), around 3 points. Win probability = normal CDF of margin / sd (also refit, around 16).

The preseason prior gets one more nudge before the season's first ridge fit: each team's CFBD talent composite z-score for the upcoming season, times 0.8 (in std devs of that feature's own net rating), added to offense and subtracted from defense. See `PRESEASON_COEF` in `model.py`.

Play filters: runs, passes and sacks only, FBS vs FBS games only, no kneels, no two point tries, no garbage time (margin over 38 in Q2, 28 in Q3, 22 in Q4).

Raw EPA (`E`) is still solved for display columns, but it's not in the rating.

## Results so far

Out of sample (2025 and 2026 so far): average miss 12.40 points, picks 73.3% of winners. Vegas: 11.74 and 75.7%. The earlier EPA-only version missed by 12.70.

Against closing lines the market is hard to beat: on the 2025+ test years the closing spread alone misses by 11.74, and blending in any share of the model makes it slightly worse (10% model: 11.75, 30%: 11.82). Model vs line disagreements of 3+ points covered 60.5% in training years but 49.5% in test years. Fit on recent windows the share is about 0 (2016 to 2026: −0.02, 2021 to 2026: −0.06). So no edge vs closing lines is proven.

Opening lines (tested Oct 2026, `lines_hist.json` has openers for 2023 on, about 2,500 games; the model's pregame number only uses games before that week, so it exists when lines open):
- The line moves toward the model. Every season 2023 to 2026, when the model disagreed with the opener by 1+ points, the closing line moved toward the model about twice as often as away (2025+: 54% toward, 27% away, average +1.0 point; at 8+ point disagreements 70% toward).
- Betting the model's side at the opener: 2025+ test games covered 54.6% of 845 (95% range 51.2 to 58.0), all 2023+ seasons 52.4% of 1,966. Against the closing number the same bets cover about 50%. So the model's information is real but the market absorbs it by kickoff; any edge lives at the open and is not proven above 52.4% yet. Small disagreements (1 to 3 points) did better than big ones (8+ covered about 51%: big gaps usually mean news the model can't see, like injuries).
- Caveat found later: with the model one game older (each team's rating from before its previous game) the 2025+ cover vs the opener falls from 55.1% to 51.4% and line movement toward the model from 61/28 to 50/36. So the edge depends on the most recent week's games. Either the model reads those faster than the opener (real), or some openers were posted before those games and the backtest's model had information the opener didn't (artifact). History can't separate the two; the forward test below can.
- Forward test (`src/track.py`, runs in CI after `kalshi.py`): every game in the next 8 days gets logged to `tracking.jsonl` (committed, append only, union merge) the first time it has a line, with that line, the model's number at the same moment and the opener for reference. Never edited. The Edges tab grades the model's side (1+ point disagreement with the logged line) vs the logged line and the closing line, plus how often the line then moved toward the model (`trkRows`, `renderTrack`). Started Oct 16, 2026. Note the closing line for finished games comes from ESPN, the logged line from CFBD. `TRACK_LOG` env var points it at a scratch file for local tests; never commit locally made entries.
- Blending the model into the opener: least squares share about 0.21 (2025+), vs about 0 against closing lines; opener MAE 11.82 vs 11.80 with 10 to 20% model.
- On the page: `DATA.open` (every game's opener, from `lines.py`), `OB` (the same backtest live in the browser, by edge size, all years and 2025+), `openCheck()` labels: "Beat the opener" only if the 2025+ Wilson lower bound beats 52.4% on 100+ games (nothing does yet), "Line tends to follow" when toward beats away by 15+ points on 100+ games, else "Unproven". Shown as Edge vs opener on the game page, a Vs open column and an Opening lines note in Edges, and in the signal list.

Things tested that didn't help: recency weighting (half-lives of 42 to 140 days), including raw EPA alongside turnover-free EPA, adding explosiveness (EPA per successful, turnover-free play) as a fourth rating input. Explosiveness still shows as a display column (`EX` in `FEATS`), its signal is just already inside EPA per play, so it moved test MAE by under 0.01 points.

Tested Oct 2026 as ways to sharpen the rating (walk forward, beta fit on 2008 to 2024 without 2020; scored on 2021 to 2024 and on 2025+; the rule for changing the model is a meaningful gain in both, not just the test years):
- "Earned points" instead of final points: offensive drive points (TD 7, FG 3) on drives with non garbage plays, leaving out garbage time and defensive and return scores. Per drive (lambda 30/60/120) or per game, in place of `PTS` or next to it. Worse in every period (test 12.44 to 12.57 vs 12.405, 2021 to 2024 12.87 to 12.95 vs 12.830). The "luck" in final scores carries real information (good defenses and special teams make those plays). Columns were tried in `build.py` and reverted.
- Adding finishing drives, havoc, or rush and pass EPA as rating inputs, alone or together: best test 12.358 (finishing plus havoc) but 2021 to 2024 unchanged (12.831); rush and pass split helped 2021 to 2024 (12.785) but not test (12.399). PTS lambda 1.5 or 6 instead of 3: no real change or worse. None passed, so the rating stays NT, SR, PTS.

Checked whether the model's miss size varies by anything, to see if win probability should use a variable standard deviation instead of one flat number. Bucketing by projected margin size: no, std stays flat whether the favorite is up by 2 or up by 35. Bucketing by how many games each team has played so far that season: yes, games where neither team has played yet (pure preseason prior, no in season data) used to miss by more and run biased, about 3 points too generous to the favorite on average. `sd_early` in `site_data.json` params captures the std difference.

That preseason bias is mostly fixed now: added each team's CFBD recruiting talent composite (z-scored per season) as a nudge to the preseason prior, tuned by walk-forward backtest on 2015 to 2024 preseason-only games and confirmed on 2025 to 2026 (never touched while tuning, see `/tmp` scratch test script if it still exists, otherwise rerun the same grid search against `model.walk`). Preseason-only MAE went from 15.44 to 14.07 points and the bias nearly vanished, -5.38 to +0.04. Returning production (CFBD's `/player/returning`) was also tried, alone and blended with talent, and made things worse both ways, so it's fetched (`preseason.json` has it) but unused (`PRESEASON_COEF["returning"]` stays 0).

## The page

`src/template.html` holds all the UI and the browser math. The browser re-solves every ridge regression live (Cholesky) whenever the date range changes, so any range from 2004 to today works, including ranges that cross seasons. The JS solver was verified to match the Python one to two decimals.

The Games tab uses precomputed pregame picks from `site_data.json`. Each past pick only used games from before that week.

The Matchup tab has an Outlier style Line history panel, all computed in the browser from games with a closing line: how favorites of that size at that site have done since 2004, each team's record against the spread (season, last 10, as favorite, as underdog, at this site), head to head with lines, and how the model's side covered when it disagreed with the line by a similar amount (all years and 2025+ test years). It only uses games before the opened game's date, and for past games it uses that game's pregame pick, not hindsight ratings. Opening a game from the Games tab fills in the spread; it can also be typed in. Below that, a Situations table (last 2 seasons) gives each team's straight up record, average margin and record against the spread vs T-Rank top 25, 26 to 50 and 51+ opponents, off a win, off a loss and off a bye, with the cells that apply to this game highlighted. Top 25 is this site's T-Rank, not the AP poll: past seasons use final ratings (`FINALRANK`, rebuilt from season N+1's prior), the current season uses current ratings. The Trends feed also gets a card when the situation that applies tonight is lopsided against the spread (4+ games, 75%+ one way).

The Trends tab is a reverse engineered, more honest take on Outlier's feed. One card per upcoming game: the spread and the Kalshi moneyline, each with a fair probability, EV and quarter Kelly; opening line vs now; a Kalshi price sparkline (`kmove`, built by `kalshi.py` from `kalshi_history.jsonl`); and the two strongest auto generated trends (last 10 against the spread, season, as favorite or underdog, at this site, head to head) with a green/red hit strip. Unlike Outlier, every trend gets a signal check: "covered k of last 10" is backtested across every team and game since 2004 (it has not predicted the next game), and other splits show a Wilson 95% range plus a warning that they were picked from many possible splits. Fair probabilities do not use the raw model. They keep only `FIT.w` of the model's disagreement with the closing line, least squares on the last 5 seasons and clamped at 0. That share was about 0.37 on 2008 to 2024 but is about 0 on 2016 onward (markets tightened), so right now fair spread odds equal the market's and spread EV is never positive. Spread to win chance uses a logistic curve fit to real results (`WINK`, about 8.3 points), because a bell curve underrated big favorites (17 point favorites won 90%, the bell curve said 86%). Kalshi EV includes the taker fee (0.07 × price × (1 − price)) and is skipped when the Kalshi price is more than 12 points off the books, which is almost always a stale price on a thin market; any positive moneyline EV means Kalshi is cheaper than the books, not that the model knows better. A streak bucket only earns "Has held up" with 200+ games behind it. All computed in the browser. The tab opens on an Insights view, one Outlier style card per trend (spread, totals or moneyline), each with the bet and price, a hit strip colored by whether that card's bet hit, and a tap to open signal check. "Over hit k of last 10" is backtested the same way as the spread streak (`OU10`). Straight up win streaks are labeled priced in. The Picks view is the per game cards with EV. Hit rate cards come first: tonight's exact number checked against each team's recent games, like Outlier's props ("Notre Dame has won by 11+ in 10 of its last 10", "Tulane's games have stayed under 55.5 in 9 of the last 10"), with an L5 / L10 / L20 / season / head to head row. Shown when L10 is 8+. `HR10` backtests this across every game: teams that had beaten that game's spread in 10 of their previous 10 covered 52.8% (895 games), 9 of 10 covered 53.0%, so these are labeled likely noise; the books already price recent form.

## Research platform (Outlier / Props.Cash style)

Built in phases on top of the existing model, all client side so it still runs on GitHub Pages. Every number is labeled by source: MARKET (sportsbook lines via CFBD, or Kalshi when no book moneyline is posted), MODEL (pregame projections), HISTORICAL (finished games vs closing lines), DERIVED. Missing market data shows N/A and is never estimated.

- Data layer in `template.html`: `gameView(g)` and `sideView(v, id)` turn a games row into labeled fields; `teamProfile(id, before)` builds every betting trend from games finished before a date and keeps the game list behind each one (`lists`) so any record can be audited. `EB` backtests raw pregame model edges vs closing spreads and totals by edge size (all years and 2025+ test); `confidence()` turns that into "No edge", "Model lean, unproven" or "Supported" (only if the 2025+ Wilson lower bound beats 52.4% on 100+ games, which nothing does today).
- Shared pieces: `trendCell` (record with the sample always visible, colored only with 5+ games), `edgeCell`, `teamLinkHtml` (any `.tlink` opens a team, any `.glink` opens a game), `heatCls`.
- Game Finder (phase 1): one row per team per upcoming game, sortable, sticky headers, filters, model's side only view.
- Game Research (phase 2, `#game/<id>`): key numbers, team comparison with national ranks (adds adjusted rush and pass EPA, `PE`/`RE` in `FEATS`, display only), Last 3/5/10/season/custom switch that drives the existing date filters and `compute()`, a G-Score by game chart, betting trends with tap to audit. For past games the ratings stop the day before.
- The game view opens with an Outlier style block (`gvOutlier`): chips for every bet with a number (each spread, over, under, each moneyline) and its price; L5 / L10 / L20 / this season / last season / H2H; the hit rate of recent games against tonight's exact number with a bar chart (`lineBars`, dashed line at tonight's number, green cleared, red missed, gray push); an L5 to H2H hit rate row; opening vs current spread and Kalshi's price path; a bet bar with the model's view and its confidence label; a signal check from `HR10`; and "X has the ball" matchup tables (offense vs defense ranks for EPA, success rate, rushing, passing, explosiveness, havoc, finishing, points, plus pace). Totals can be viewed against either team's games. Taps on games in the Games and Trends tabs open this view; Matchup stays one tap away from it.
- Team Research (phase 3, `#team/<id>`, also the header search box): rating, offense, defense and SOS with national ranks (or a one tap "Rate <season>" when the team's season isn't in the current ratings range), record, ATS and O/U; Last 3/5/10/season/custom periods; margin vs closing spread and G-Score charts (`divBars`, a shared diverging bar chart); and a game by game table with spread and ATS result, total and O/U result, the pregame model spread, raw per game EPA, success rate, explosiveness, defensive EPA, G-Score and opponent rating, upcoming games grayed out. Any season back to 2004. Team names in Ratings, its game logs, Finder, Trends, game and team views link here; the Ratings row tap still opens the inline game log.
- Trend Finder (phase 4, tab `tf`): Props.Cash style queries over every finished game since 2004 from each team's side (`tfSides()`, built once on first open): team, opponent, seasons, dates, site, conference game, favorite or underdog, spread and total ranges, opponent T-Rank tier, rating, offense rank, defense rank and SOS, previous game result, rest, and whether the model's pregame pick liked the team. Returns games, straight up, ATS and O/U with Wilson 95% ranges, average margin and ATS margin, the model's pregame record in the sample, and every game in it (200 at a time). With no team picked each game counts from both sides.
- `export2.py` writes `final`: each season's end of season rating and adjusted off and def EPA (season to date for the current one), solved with the same prior the page uses. `FINAL` in the page adds ranks and SOS. Opponent strength in history (Trend Finder, situations, top 25 splits) comes from here, and is labeled as hindsight. It replaces rebuilding past seasons from the next season's prior, which since the talent nudge also carried the next season's recruiting adjustment (that path stays only as a fallback for older builds).
- Edges (phase 5, tab `edges`): upcoming games ranked by model vs market gap, separately for spreads, totals and moneylines, with market and model lines, the raw model probability next to break even (or the market's no vig probability for moneylines), projected value, the edge size's 2025+ track record, and a "why" column splitting the model's margin by ingredient (`t.comp`: EPA, success rate, points, plus home field). Labeled model edges and leans, never picks. Moneylines show "Untested" since only the current season's book moneylines are stored. Finding: the biggest spread edges come mostly from the points ingredient, which uses final scores (garbage time and turnover luck included).
- Watchlist (phase 5): games can be saved (☆ in Finder and Edges, + Watchlist on a game) into the same `gtr_wl` storage as the original saved picks (`type: 'game'`). Saved games show the spread and total when saved vs now (line movement), model spread, edge, model total, model win and the result once played; shown in Edges and under the original picks list in Matchup.
- Projected scores everywhere use `expPts(t, opp) = t.ptsO + opp.ptsD - ptsMu` (additive, like the ridge model), so they add up to the pregame totals. The Matchup and Games tabs used to average offense and defense, which halved every deviation and squeezed projected scores toward the mean.
- `compute()` also gives `sos` (average current rating of opponents in range) and `form` (average G-Score, last 3 games), with ranks.
- Model totals: `model.walk` saves a pregame total (`ptot`: both teams' expected points from the points ridge, only earlier games) and `export3.py` writes `ptot` for every game. Checked 2013 on: unbiased (about −0.2), but the market total is more accurate (2025+: model misses by 13.11, market 12.46) and total edges have not beaten 52.4% at any size, so they're shown as unproven leans.
- `lines.py` also stores sportsbook moneylines for the current season (`ml`), preferred over Kalshi for implied probability (vig removed).
- Havoc and finishing drives (phase 6): `build.py` now adds per team-game `hav` (plays with a tackle for loss on a run, sack, interception, forced fumble or pass breakup), `trips` (drives reaching the opponent 40) and `tpts` (offensive points on them, TD 7, FG 3; drive result labels changed over the years, e.g. "RUSHING TD", "FG GOOD", so they're mapped explicitly and defensive scores count 0). `export2.py` appends them to each row (indices 16 to 18). The page solves them as opponent adjusted display stats (`HV` havoc rate, `FD` points per trip, lambdas in `LAMX`). Pass breakups and forced fumbles are barely recorded before about 2014, so havoc compares fairly only within a season. League levels: about 3.6 to 4.0 points per trip, havoc 10 to 13%.
- Phase 6 also: Finder rows switch to abbreviations and short dates on phones; the Method tab documents the research tools and data rules; page usable in about 1.7 s, a full ratings recompute about 75 ms.
- Vs opponents like this (game page, right after the Outlier block, `gvVsOpp`): each team's SU, average margin, ATS and O/U vs tonight's opponent, T-Rank top 10 / top 25 / 26 to 50 / 51 to 100 / 101+, teams rated within 5 points of tonight's opponent, top 25 offenses and defenses, tonight's opponent's conference (when different), conference and non conference games. Periods: this season, last 3 seasons, since 2004. Opponent strength is each season's `FINAL` rating (hindsight, labeled). Rows that apply tonight are highlighted; game counts open the list behind each record (`vsoAudit`).
- Games Like This (historical matchup analogs, in Game Research):
  - Fingerprints: `model.walk(..., snap=True)` saves both teams' pregame snapshot for every game via `model.snapshot()`: o and d for E, NT, SR, PTS, EX plus the fingerprint only stats in `FP_FEATS` (pass and rush EPA, havoc, finishing; they get a last season prior too, without the talent nudge), FBS games played, and opponents' average NT/SR/PTS nets so far (SOS). Values are deviations from that fit's league average, so eras compare. `export3.py` writes them as scaled integers to `site['fp']` (`cols`, `scale`, `rows`), rating and SOS already multiplied by beta; upcoming games use every 2026 game so far, the same as the walk forward would. About +1 MB gzipped on the page.
  - Look-ahead: snapshots only use rows dated before that week's first game, the analog pool only holds finished games dated before the opened game, and results are never features. `src/test_analogs.py` (runs in CI before export) poisons a week 8 game's stats and checks that its fingerprint and every earlier week's stay identical while later weeks change, then rebuilds 25 snapshots by hand from earlier rows. A browser check also confirmed flipping a game's score doesn't change its analogs.
  - Engine (template, all config in one place): `AN_FEATS` (every feature: label, dimension, standardization group, format), `AN_PRESETS` (Balanced, Efficiency, Style, Market, Model weights), `AN_MARKET_ADD` (the "+ Market" toggle), `AN_MIN_SIM`/`AN_GOOD`/`AN_EXC` (70/80/90), `AN_MIN_COVER` (0.8). Each game is oriented so Team A is the model's pregame favorite. Per play matchup stats are "A offense rating plus B defense rating" and the reverse, z-scored within season; point scale features (ratings, gap, site, SOS, games played, model and market numbers) across all seasons. Distance is the weighted root mean square z gap over the features both games have (missing features are skipped, never zero; a candidate needs 80% of the target's weight), similarity = 100 × e^(−d²/2). The pool (16k games) builds in about 0.2 s on first use and a search takes about 2 ms.
  - Calibration: under Balanced the median game's best match is about 91% and its 10th best about 86%. Market and Model presets use 4 to 5 features, so they find near exact matches (99%+) easily: those percentages mean closeness on fewer things.
  - Page: summary (quality label, A-like side SU and ATS, favorite SU and ATS, O/U, average margin and total, A-like margin minus its pregame projection), labeled descriptive with the sample noise range; up to 10/25/50 analog cards (5 shown, rest behind Show all), each with a WHY THIS MATCHES table (this game vs that game per feature, gap in sd). Nothing below 70% is shown, even if that leaves the list empty. Advanced lets you switch off whole dimensions.
  - Finding: analog cover rates do not predict covers. Every lined game 2010 on, Balanced (Good+ analogs, 10+ lined of 25): when analogs covered 55%+ the A-like side covered 50.4% (5,443 games); at 45% or less the other side covered 50.3% (1,812). Market preset 51.4% of 7,946. 2025+ only: Balanced 53.7% of 652, Market 48.7% of 719. So analogs are context, not a signal.
  - Teams Like These: each team's pregame snapshot vs every earlier team snapshot (`TL_FEATS`), best per team season, never the same team's own season; shows rest of that season's record and final rank as labeled hindsight.
  - Why the model (`gvWhy`): model margin = rating gap ± home field from the same snapshot, plus the 3 most extreme matchup stats that season, plus the ingredient split for upcoming games. Signal agreement (`gvSignal`): counts the edge size's 2025+ record and line movement since open; Strong, Moderate, Weak, Conflicted by stated rules. Analogs are listed but not counted (finding above). Data coverage chips (`gvCoverage`): season play by play coverage, games played, which markets are posted, fingerprint features present.
- Player props (game page, right after the bet block, `gvProps`, Outlier style): pick a team, a market (pass yds, completions, pass TDs, rush yds, rush att, rec yds, receptions, rush + rec yds, rush + rec TDs) and one of the team's top 8 players in it; bars of each game against the line with L5 / L10 / L20 / this season / last season / H2H hit rates; over or under; tonight's opponent's matching defense rank (opponent adjusted pass or rush EPA allowed) and what it allowed per game in that market this season. No sportsbook prop lines exist in our data, so the line defaults to the player's median this season and can be typed over (labeled). Built by `players.py` from play by play: sacks are not rushes; receivers count every targeted game (a target with no catch is a 0), but a game with no touch and no target can't be seen. Checked against 2025 leaders (Mestemaker 4,398 pass yds, Jeremiah Smith 1,279 rec yds). About +0.5 MB gzipped.
- Quarterback context (`qb.py`, `gvQB`): upcoming game pages show each team's main passer last game and flag a change from the season's attempts leader or a split game (under 70% of passes). Tested first as a reliability warning and it failed: across 13,306 lined games since 2008, games right after a main passer change were not worse for the model vs the line (model minus line average miss +0.20 vs +0.28 without a change; 5+ point edges covered 53.1% vs 53.7%). So it's shown as context for checking the news, not as a warning.
- Not available: AP rankings ("top 25" means T-Rank top 25).

## Known gaps and next ideas

- The current season is one setting: `src/season.py` (`SEASON`, env var override). Change it in August once the new schedule file exists, then run and check the pipeline before the first games.
- Preseason recruiting talent is in, returning production is fetched but didn't help. Still not tried: transfers, QB-specific returning production instead of whole-team.
- Not built yet: remaining Five Factors columns (field position, finishing drives), player stats (QB, rusher and receiver EPA are possible; defenders aren't), projected final records, a wins-above-playoff-team résumé stat.
